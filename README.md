# DSH-AB

把 DeepSeek Harness（dsh）装成一个可以双击运行的 Windows 应用，并且**改坏了能退回去**：正在跑的那个槽是「活动槽」，改动一律
做在另一个槽、在一个空闲端口上验证可用之后再登记切换（重启才生效）；DSH-AB 只做**入口、托盘、槽位切换、安装/卸载**，不改 dsh 任何文件。

## 安装

1. 下载 `DSH-AB-<本项目版本>-<dsh版本>-setup.exe`，双击按中文向导走完；装完双击安装目录里的 `DSH_AB.exe`（默认目录在 `%LOCALAPPDATA%` 下的产品目录，向导里可改）

> ### ⚠️ **不支持覆盖安装**
> 目标文件夹**必须为空**：已有任何文件或文件夹就直接拒绝，**不覆盖、不合并**（升级见下面「下载与升级」，不是覆盖安装）。另外两条：**端口必须
> 没被占用**（安装程序真的在 127.0.0.1 上试绑一次，占用就拒绝安装）；**允许多份安装**——换个空文件夹就能再装一份，两份
> 可以同时运行，各有自己的数据、开始菜单入口与托盘图标。

### 静默安装（无人值守）

    DSH-AB-<本项目版本>-<dsh版本>-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DIR=<空文件夹> /PRODUCTION=<生产端口>

- `/DIR=` 必须是**空文件夹**（非空被拒并返回非 0 退出码）；`/PRODUCTION=` 不写就用安装程序的默认端口 **3090**，
  值非法（不是 1–65535）时**报错退出**，不会改用默认值。
- 端口被占用时：**向导**在端口页预填**第一个空闲端口**并写明改成了哪个；**静默安装不换端口**，占用就报错中止。

## 下载与升级

发布都在 **GitHub Releases**：**一个 DSH-AB 版本一个 Release**，里面是**上游各个 dsh 版本**各一个安装包（alpha、rc 与
正式版都算），外加**一个更新包** `DSH-AB-<本项目版本>-update.zip`（dsh 本体在槽位里，所以更新包与 dsh 版本无关，
一个 DSH-AB 版本只有一份）。Release 说明最上方是「最新在前」的下载表——下面的文件列表由 GitHub 按文件名排序，最新版
可能被排到后面去，看那张表就不会拿错。

**升级不是重装**，两条路都行：

- **就地更新**（同一份安装原地换程序文件，推荐）：取上面那个更新包，交给在维护这份安装的 dsh/AI 做。规则是固定的：
  **先提交一次 git 快照** → 删掉安装根里除两个槽位、`.git` 与 `state\` 以外的目录 → 按新版覆盖文件（`DSH_AB.exe` 可能
  正在运行，用「先改名、再把新的放到原位」的办法换，不结束进程）→ 把台账里的安装根占位符替换成真实路径。
  **dsh 与托盘全程不用重启**，`dsh-ab.toml`、`state\` 与两个槽位原样保留；**回退就是取回那次快照**。
  **不随包发更新脚本**：这套规则写在随包 skill 里，由 AI 判断并执行。
- **装进一个新的空文件夹**：安装程序只接受空文件夹，永远不覆盖、不合并已有安装；想并排留一份旧的就这么做。

轮到自己这一次，看 `CHANGELOG.md` 就行（本轮 0.1.2 写的就是就地更新这条链）。

## 使用

双击 `DSH_AB.exe`：后台启动 dsh 并打开浏览器，托盘出现图标，**不会闪控制台窗口**。托盘菜单固定六项，左右键同一个菜单：

| 菜单 | 作用 |
| --- | --- |
| 打开浏览器 | 打开正在运行的 dsh 页面 |
| 当前状态 | 活动槽、端口、两个槽位状态、切换状态、日志级别、配置状态、安装根、版本、日志路径 |
| log：off / auto / full | 单击循环日志等级，**不弹任何窗口** |
| 槽位切换 / 槽位切换：待生效 | 登记切换或撤销登记；**只有点「重启」才生效** |
| 重启 | 重启 dsh，已登记的槽位切换在此时生效 |
| 退出 | 停止 dsh 并退出托盘 |

**名字**：本机只有这一份时叫 `DSH-AB`（开始菜单里是裸的 `DSH-AB.lnk`）；有别的份共存时叫 `DSH-AB (生产端口)`；
端口用不了或与别的安装撞端口时改叫 `DSH-AB (tag)`，并弹窗请你改 `dsh-ab.toml` 里的端口。**多份共存的只有名字不同**：
快捷方式永远直接放在 `开始菜单\程序\` 下，没有子文件夹。
**名字不看安装目录名**；「应用和功能」「当前状态」弹窗标题和快捷方式都用这个名字本身（**括号在名字里**，名字里不带版本号——
版本由「应用和功能」的版本列显示）。**托盘提示只有状态与生产端口**（不带安装名）：`DSH 运行中（端口 <生产端口>）` / `DSH 未运行（端口 <生产端口>）`。

**三条线别搞混**，三种升级各管各的：**DSH-AB 自己的升级**用 Release 里的更新包就地更新，dsh 不用重启（见上面「下载与升级」）；
**dsh 本体的升级**是在同一份安装内把新版 dsh 覆盖进**非运行槽**，在一个空闲端口上验证通过后登记切槽、由你点「重启」，
**不要另建一套安装目录**；**安装程序**只装空文件夹，不做覆盖安装，升级也不靠它。安装程序的规则写在本 README 与
`docs\MAINTAINING.md` 里（维护宿主的人/AI 看），dsh 侧的规则写在随包 skill 里，**那份 skill 不提安装程序**。

## 优点与缺点

- **改坏能退**（两个完整槽位，切槽只改启动目标、不同步数据）、**双击即用**（无控制台、浏览器自动打开）、**全中文**、**完全离线**
- 内置 Node 运行时、dsh 应用树、npm 依赖闭包与便携 Git（MinGit：有 `git.exe`，**没有 bash / git-bash**）；安装包较大（几十 MB 级，随内置的 dsh 版本变化）
- **多份各自独立**：各有自己的「应用和功能」登记项、开始菜单入口与桌面快捷方式，卸载一份不影响其它份
- **卸载干净**：程序文件、注册表项、快捷方式全部清除；**用户数据默认保留**，删不掉的项会逐条列出让你手动删
- **不支持覆盖安装**、**不会自己联网更新**（升级由你或 AI 用 Release 里的更新包就地更新）、**不自动更新 dsh**、
  **未做代码签名**（首次运行可能触发 SmartScreen）、仅在 **100% DPI** 下验证过
