# DSH-AB

DSH-AB 是一套 DSH 安装的入口、切槽与托盘宿主，只负责启动/停止 dsh 与探测端口；它从不读写 dsh 内部的东西。

## 文件结构

```
<安装根>\
  DSH_AB.exe    入口程序：托盘宿主 + 启动器（GUI 子系统，双击无控制台）
  dsh-ab.toml   配置。归用户管；改完要重启 DSH_AB.exe 才生效
  README.md     本文件（随包安装）
  LICENSES.txt  第三方许可证（随包安装）
  .gitignore    快照仓库的忽略规则（随包安装）
  docs\
    PLUGINS.md  插件与改动台账。AI 维护
    TODO.md     本轮待办。AI 维护
  slot-a\       随包安装的完整实例，默认的活动槽
  slot-b\       装好时是空目录。改 dsh 前由 AI 把活动槽整份复制进来
  runtime\git\  内置便携版 Git。AI 打快照用
  state\        活动槽指针与待生效的切槽登记。DSH-AB 写
  logs\         日志目录。DSH-AB 写；级别 off 只记 error，auto 再加 warn/debug，full 全记（含子进程输出）
```

## 槽位

同一时刻只有一个槽是**活动槽**：它对外服务生产端口，并持有正在使用的数据；安装后 slot-b 是**空目录**。登记一次切换只写 state\pending.json，不结束任何进程；**只有点托盘的「重启」才会切槽**——关掉再打开不会切换，登记保留、也可撤销。

## 托盘菜单（六项固定，左键与右键同一个菜单）

| 序 | 菜单项 | 行为 |
| - | ---- | ---- |
| 1 | 打开浏览器 | 先预检端口与进程，两者都正常才打开 |
| 2 | 当前状态 | 活动槽、端口、两个槽的状态、切换登记、日志级别、配置状态、安装根、版本、日志路径 |
| 3 | log：off / auto / full | 单击循环三档（off 只记 error；auto 再加 warn/debug；full 全记，含 dsh 子进程输出）；**完全不会**弹窗；只对本次运行有效 |
| 4 | 槽位切换 / 槽位切换：待生效 | 登记切换，或撤销登记；只写登记，绝不结束进程 |
| 5 | 重启 | 停掉 dsh，再启动本次该跑的槽（先确认） |
| 6 | 退出 | 停掉 dsh 并退出托盘（先确认） |

## 需要知道的行为

- **名字与开始菜单**：本机只有这一份时叫 `DSH-AB`（开始菜单里是裸的 `DSH-AB.lnk`）；有别的份共存时叫
  `DSH-AB (生产端口)`。多份共存的只有名字不同：快捷方式永远直接放在 `开始菜单\程序\` 下，没有子文件夹。
  端口用不了或与别的安装撞端口时改叫 `DSH-AB (tag)`，
  启动时弹窗请你改 `dsh-ab.toml` 的端口。名字不看安装目录名，每份只动自己的快捷方式。**托盘提示只有状态 + 生产端口**（不带安装名）：
  `DSH 运行中（端口 <生产端口>）` / `DSH 未运行（端口 <生产端口>）`——名字在开始菜单、快捷方式、「应用和功能」和
  「当前状态」弹窗标题里。
- 绝不自行重启 dsh，发现故障只会告诉你（同类故障在 `health.popup_throttle_min` 分钟内不重复提示）；启动失败的弹窗给出
  子进程最后的输出、日志路径、安装根与下一步，端口被占会直接说明并指向 `ports.production`。
- 安装程序只接受空文件夹，并要求填写的生产端口没被占用；它**不阻止**你再装一份。向导里默认端口被占用时
  端口页会预填第一个空闲端口；**静默安装不换端口**，占用就报错中止。**没有覆盖升级**：升级 = 装到新的空文件夹。
- 卸载先提醒你在托盘「退出」，再问用户数据（默认保留，位置 `<安装根>\slot-*\data`）；删不掉的项会逐条列出。
- **dsh 的自我升级**是把新版 dsh 覆盖进**非活动槽**，在一个空闲端口上验证后登记切槽、由你点「重启」；**不要另建安装目录**（细节在 `SKILL.md` 里，那份 skill 不提安装程序）。
- **就地更新 DSH-AB 自己**：Release 里除安装包外还有一份 `DSH-AB-<版本>-update.zip`——安装根里除两个槽以外的程序文件，
  一个 DSH-AB 版本一份（dsh 本体在槽里，包与它带的 dsh 版本无关）。覆盖到安装根上就是更新：dsh 与托盘都不用重启，
  `dsh-ab.toml` 与 `state\` 原样保留，新版托盘下次启动生效。**回退靠安装根的 git 快照**：更新前先提交一次，
  回退就是 `git reset --hard <那次提交>`（快照只跟踪程序文件与 `docs\`，`runtime\` 与两个槽不在里面）。整套流程写在随包 skill 里，不随包发脚本。
